## 1. Objective
Meaningful, reported viability experiments for the island population and, if achievable by mechanism, a viable favourable scenario (M4.37), **without forcing outcomes** (D5.33, owner D4). Diagnose the conception-coordination bottleneck (completed fertility 0.50–0.70 against about 2.3 needed) and, if the cause is a defective mechanism, fix it as a mechanism behind a tuning flag, never by tuning outcomes.

## 2. User-facing outcome
The owner gets an honest demographic report: per ecology (favourable, balanced, hostile), over 20 seeds and at least 5 generations, survival, completed fertility, causes of death, carrying capacity and care effects, with the mechanism change (if any) stated and its effect measured. If the favourable scenario becomes viable, "Living island" can later use it (lead decides at a re-pin point).

## 5. Allowed scope
1. **Demography resume steps 3–5:** run the fertility sweep `plan_fertility.json` on `demog_favourable` (the combined biological arms); choose **one justified biology block** (values with a written biological or design justification, not picked for survival) for all three `demog_*` scenarios; run 20 seeds × ≥ 5 generations per ecology; run M4.38 (one-factor arms), M4.40 (preferences), M4.44 (care arrangements).
2. **Diagnose the conception-coordination bottleneck** from events and the DemogRecorder (share of fertile woman-days in each state; how often both partners hold "try for a child" at the mother's check with the partner in sight). If a defective rule is found (for example the partner-in-sight check at a single daily instant), fix it as a **mechanism** (e.g. a remembered mutual intent for a window, or a check at any shared-hut presence) behind a new flag `Households.Life.ConceptionMode` (default 0 = current behaviour, `IOmitWhenDefault`), with an EditMode fixture proving the old mode is byte-identical and the new mode changes only the coordination rule.
3. **Rerun M4.26's death clause** on the established band with enough seeds to be non-vacuous (currently passes only with 0 disease deaths); report honestly.
4. Scenario and plan files `demog_*.scenario.json` and `plan_*.json` (new plans allowed, e.g. `plan_conception.json`, `plan_biology_block.json`).
5. Report section "Demography investigation" in POPULATION_DESIGN updated with the evidence; the D4 status cells (M4.36–M4.45) in ACCEPTANCE_TESTS.
6. **Later (only if C6 / C7 have merged):** use the C6 communal store and C7 care organisations as treatment arms (ORGANISATIONS §9), switches set in the arm.
