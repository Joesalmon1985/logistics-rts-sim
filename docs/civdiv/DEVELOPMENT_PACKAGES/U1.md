# U1: Camera, selection, input and time controls (U1a); embodied cameras and control input (U1b)

Package spec for the Civilisation and Divinity run (owner brief 26 Nov 2026 §40). Self-contained. Paths start at the repository root (`Assets/…`, `DotNet/…`, `docs/…`). "Contracts" = [SHARED_ARCHITECTURAL_CONTRACTS.md](../SHARED_ARCHITECTURAL_CONTRACTS.md) (binding). This is a **view package**: `Assets/God/Game` only reads sim state, sends commands and animates events; it never mutates the sim.

## 1. Identifier

**U1**, two parts at two times: **U1a** (Tier 1, Checkpoint **B**, about 3.5 h) and **U1b** (Tier 2, Checkpoint **D**, about 2.5 h; restarts when D4a merges). Branches `unity/u1a` and `unity/u1b` (the index names the pair `unity/u1`; use one branch per part so each merges separately), worktree `wt-lrs-u1` (reuse the warm folder for U1b on the new branch after U1a has merged).

## 2. Objective

- **U1a:** functional player controls for observing and addressing the world (brief §26, D5.23): a free overhead camera with rotation, pitch, close zoom to one person and follow; a selection model (person, hand-picked group, household, area, object, location); a device-independent input layer and a pure `PlayerCommandBuilder` that stamps divine commands with the `HumanGod`; time controls pause/1×/2×/5×/10× with commands **queued while paused**; names, favourites and follows kept in a non-hashed `ui` save extra.
- **U1b:** third-person cameras for a possessed body and the avatar, smooth switching driven by sim events, and the move axis quantised into `DivineControlInput` sectors with hysteresis and the lease rule (contracts §11.3), so a possession or avatar walk is a deterministic command stream that replays headless.

## 3. User-facing outcome

The player can orbit (Q/E), tilt (R/F), zoom from the whole island down to one villager, double-click a person to focus, press F to follow them as they walk, box-select a group, double-click to select a household, brush an area; pause and think while still moving the camera and selecting; queue a divine command while paused that applies when time resumes; run at 1×, 2×, 5×, 10×; star and rename favourites (names never change the game). In Checkpoint D, possessing a person or manifesting the avatar swings the camera behind the body and WASD steers it; releasing lifts the camera back to where it was.

## 6. Allowed scope

**U1a:**
- `Assets/God/Game/Camera/CameraDirector.cs` owning `GodCameraRig` as its overhead implementation (existing tests stay valid: yaw 0 and pitch 50 reduce to today's view); orbit model (focus, yaw, pitch 25-80°, distance, FOV), close zoom to about 4 m, the four zoom bands (island, region 220 m, settlement 90 m, individual 14 m), `Home`/`H` whole island, double-click focus, `F` follow (`FollowCam`: focus tracks `NpcLayer.TryPosition` with 0.25 s smoothing; pan detaches; death leaves the camera in place), springs on `Time.unscaledDeltaTime` so they work while paused. Pickers keep working at any yaw (`WorldToScreenPoint`).
- `Assets/God/Game/Input/`: `IInputSource` (mouse+keyboard; a `ScriptedInput` for tests), `PlayerInputFrame` (plain data), `PlayerController` → `PlayerIntent`; nothing else reads `UnityEngine.Input` for the new controls. Keep the old `Update` code paths behind the stage 3 faction mode until the tests pass (do not break the 79 existing PlayMode tests).
- `SelectionModel` (Kind: None, Person, Group, Household, Institution, Object, Area, Location; ids, primary, anchor; `Changed`): click, Shift/Ctrl toggle, box select (explicit id list from drawn positions), Alt-drag area brush (`AreaSpec { CentreNode, RadiusSteps }`), double-click household, click ground location. `SelectedNpc` etc. become views of it. **Scope is resolved by the sim** at the apply tick; Unity never enumerates an area or household to build a command (CC-4).
- `PlayerCommandBuilder` (pure function of intent + selection ids; EditMode-testable): builds divine commands with `God = ` the current holder of the `Human` seat (contracts §2.1, `GameSetup.HumanGod` then `SwitchGod`), checks with `Gate.Check` before `Submit`. It is the shared path U2's popover and radial menu submit through (U2 owns the UI, U1 the builder). Its command builder rebases on F1a's command types.
- **Time controls** (in a new partial `Assets/God/Game/Hud/GodHud.Time.cs` plus minimal edits): speed set `{1, 2, 5, 10}` in god-only mode (keep stage 3's `{1,2,4}` / watch `{1,2,4,8,16}`), pause (Space), step (`.`), the calendar label; speed is UI only, never a command.
- **Pause rule for god-only mode:** commands submitted while paused are validated at once, kept pending (shown as pending chips by U2), and applied at the next tick that runs (contracts §11.3 "Commands sent while paused apply at the next tick that runs"; PLAYER_UI UI-6). This needs an edit in `GodBootstrap.Update` so the M1 one-tick-on-command rule does **not** apply in god-only mode; the stage 3 mode keeps the M1 rule and its tests. This edit is outside U1's owned folders: keep it to a few lines, behind the `GameSetup.Control == GodOnly` check, and flag it in the hand-back.
- **`ui` save extra** (`Assets/God/Game/Save/UiExtra.cs`, an `ISaveExtra` with key `ui`, registered through `GodBootstrap.RegisterSaveExtra`): player aliases, favourites, follows, notes, selection and the camera pose; never in `GodState`, never hashed, never reaching the sim. Procedural names come from F1's `Names.Person(seed, npcId)` / `Names.God(seed, godId)` (pure functions); the card shows alias over the true name. Roster chips (favourites, followed; max 12) along the left edge with click-to-jump.
- Room for later overlays and modes: `CameraDirector` and `SelectionModel` must accept new `Kind`s and new overlay layers without changes to their core (an enum value and a registered handler), so the industrial workstream (I6: industrial overlays such as electricity, logistics and deposits; vehicle inspection and selection) can add an `Object` subtype (vehicle, power station, mine) and a follow-a-vehicle camera mode later (the industrial presentation is being specified in a forthcoming PLAYER_UI_DESIGN §25 and VISUAL_WORLD_DESIGN §18 for owner D6.19). Do not implement them.

**U1b (after D4a merges):**
- `ThirdPersonCam` for possession and avatar (orbit behind the body at 6-10 m, pitch 15-35°, shoulder offset, wheel distance, right-drag orbit, ground and building obstruction shortening with no sim query; lower for a child).
- Mode switching driven **only by events** (`PossessionStarted`/`Ended`, `AvatarManifested`/`Dismissed`/`Destroyed`): critically damped blend 0.8 s on unscaled time; `ReturnPose` remembered; "peek" (hold middle mouse) lifts the camera while the body keeps its lease. The camera never moves before the matching event.
- `ControlSampler`: camera yaw + move axis → world direction → sector `0…HeadingSectors−1` (north = board +Z, clockwise) with hysteresis (change sector only beyond 14° past the boundary), `Gait` 1/2, click-to-move (`Kind = MoveTo` with a node), `Stop`, `Action` (act + target from the selection); submit one `DivineControlInput` **only** when kind, sector or gait changes, or when the lease would expire next tick; at most one per body per tick, last wins; sampled per sim tick, not per frame, so the stream is frame-rate independent. A speed cap while embodied (default 2×, configurable).
- Leave room for a later **vehicle-operator** camera (owner D6.8 possession of operators is a later D4 extension): `ThirdPersonCam` takes its target from a body id and a size, not from an assumption of a walking human.

## 12. Save/load implications

Only the `ui` save extra (aliases, favourites, follows, notes, camera pose, selection): JSON under key `ui`, written and read by `UiExtra`, **not hashed**, never in `GodState`. Loading a save restores the camera and annotations; the sim hash is identical with or without the extra (test U1-T9). Possession and avatar states restore from the sim; the control lease is reset on load (the player must steer again).
