## 1. Objective
Persistent NPCs work productive assets (a field, a workshop, a store), own and use goods through **ownership beliefs**, and haul goods to where they are used. Theft is **classified** by the sim (truth, analytics only), never judged. This is the Tier 1 "physical resource and labour economy" (brief §17) on which employment (C3), lending (C2), organisations (C6) and the later industrial packages build.

## 2. User-facing outcome
In a population game with `Civ.Enabled = 1`, the player sees NPCs build a workshop or field from real materials, work it, store its output in the asset's store and carry goods to it; the person card's Economy section (data from `CivCard`, drawn by U5) lists possessions, assets owned and use rights. Checkpoint C: "persistent NPCs work, trade, own goods and operate productive assets".

## 5. Allowed scope
1. **`Civ.Enabled`** behaviour: `CivModule.StartGame` creates `GodState.Civ` and its C1 sub-object when the switch is on and a population exists; `CivMind` per NPC.
2. **Productive assets** as C1 objects, each with its **property record** (ECONOMY §3.5: owner, basis, shares, use rights, disputes): `ProductiveAsset { int Id; AssetKind Kind; int Node /*0 when the owning package keeps the location, e.g. a vehicle later*/; Owner Owner; OwnershipBasis Basis; long SinceTick; int Store /*BinId, BinKind.AssetStore*/; UseRight[] Rights (≤ 8); Owner[] Disputes (≤ 4); int Condition; long BuiltTick; byte Flags }` in `CivState.C1`, with the API `Assets.Create`, `Assets.Transfer` (owner change with a basis), `Assets.GrantUse`/`EndUse`, `Assets.Destroy`, (`Assets`, ascending id; counter `NextAssetId` in `CivState.C1`, never reused). `AssetKind` is a **data table** (`Civ/Assets.cs`: `AssetDef { Kind, ObjClass (90–99), BuildCost (ware, count)[], WorkTicks, Recipe (inputs → output ware, count), StoreCapacity, Staff slots }`). First kinds: **Field** (worked plot; yield by work ticks), **Workshop** (a recipe converting inputs into an output, e.g. logs → planks or a tool), **Store** (an asset that is only a store). Perceived through `CivHooks.SenseExtra` as `ObjClass` 90–92; beliefs `BeliefKind.Asset`.
3. **Building an asset**: an NPC with the materials in reach builds it at a node (`Build` learning verb 12 or a C1 intent in 170–178), consuming materials with `Goods.Consume(..., ConsumeReason.Built)`; ownership by basis `Built` (builder; a household's builders → `Owner.Household`).
4. **The `Work` verb (96)** and its intent: an NPC with a believed right (owner, household member, or holder of a `Work` use right) works the asset within `Reach.Touch`; on each completed work unit the recipe runs: inputs consumed from the asset store or carry, output `Goods.Produce(..., ProduceReason.Crafted for workshops / HandGathered for fields, actor = worker)` **owned by the asset's owner** (the wage relation of ECONOMY §4 "Property": output belongs to the owner, not the worker). Skill growth and switching cost per ECONOMY §4.2 only if a skill record exists; otherwise work speed is the base (record the default).
5. **Hauling**: `MoveReason.Deliver` moves by a carrier within reach to the asset store (an owner provisioning its workshop; C3 later pays others for it).
6. **Use rights**: `UseRight { Owner Holder; UseKind Kind (Work, Store, Gather, Pass); Owner GrantedBy; int UntilDay; int Terms }` with the API `Assets.GrantUse` / `Assets.EndUse` (emitting 272/273). In C1 the paths are: household co-use for a household-owned asset, and an explicit grant by the owner's gesture (`Offer` with the asset as topic, accepted by the recipient through M5's decision) — C3 calls the same API for employment `Work` rights.
7. **Ownership beliefs** in `CivMind` (≤ 8 `OwnBelief { int Asset or Lot class; Owner BelievedOwner; byte Confidence; long Tick }`, eviction lowest confidence then oldest, ties by id) formed only from perception (saw it built, saw the owner use it, was told by gesture); **`Permits.Believed` extended** with basis `Owned`/`UseRight` from these beliefs (still a query, never enforced by `Goods`).
8. **`Permits.Truth`** (sim-side, layer 1): the true permission of an actor over a lot or bin from ownership, use rights, household store access and (later) org roles. Never callable from policies or mind hooks (reflection test).
9. **Theft classification**: when a `PickUp`/`TakeFromStore`/`Withdraw` moves an owned lot with `OwnerRule.Keep` and `Permits.Truth` says not permitted, the sim emits `TheftCommitted` (274, analytics-only truth fields, Full) from `CivHooks.ActionEnded`; nothing reacts to it (no rule reads the event buffer).
10. **O7 / invariant C4 relaxation**: with `Civ.Enabled = 1`, a `Drop` keeps the lot's owner; after `Civ.C1.LostPropertyDays` (default 3) unclaimed, the lot becomes ownerless with `SetOwner(..., OwnershipBasis.Abandoned)`. With the switch off, M4/M5 behaviour (ownerless on drop) is unchanged. Update the invariant check accordingly (C4 holds only when Civ is off).
11. **`SourceClaimed` (275)** for first-arrival claims on sources (ECONOMY §12 "Land access"), recorded only; no exclusion rule.
12. **`CivCard.Fill`**: possessions, assets owned, use rights held, believed owners of nearby assets (layer-tagged).
13. **`CivSystem` (order 257)**: day start: lost-property expiry, asset day bookkeeping; with **partial-method slots** `DayStartC2`, `DayStartC3`, `DayStartC5` (and per-tick slots) that C2/C3/C10 fill in their own files. The dispatcher bodies of `CivHooks`/`CivMindHooks` are C1's; C2, C3, C5 add partials (`CivHooks.C2.cs`, `CivMindHooks.C2.cs`, …).
14. Scenarios: `DotNet/God.Runner/Scenarios/civ_assets.scenario.json` ("operates a productive asset") and a check that scenario 2 (trade) still holds with `Civ.Enabled = 1`.

## 22. Used later by industry (keep the interfaces general)
The industrial workstream (I1–I6, K1 knowledge and designs, K2 money and accounting; drafts now in `docs/stage4/INDUSTRIAL_RESOURCES_AND_PRODUCTION_DESIGN.md` §3.4–3.5, §4.4, `VEHICLES_AND_HARVESTING_DESIGN.md` VEH-1 and §4, `ELECTRICITY_DESIGN.md` §4 (links and stations as C1 assets), `INDUSTRIAL_MILITARY_DESIGN.md` (defences as C1 assets), `MONEY_AND_ACCOUNTING_DESIGN.md` §12, `KNOWLEDGE_AND_TECHNOLOGY_DESIGN.md`, `WASTE_AND_CIRCULAR_DESIGN.md`) builds **mines on deposits, wells, refineries, factories, power stations, power links, defences and vehicles** as C1 productive assets. Those drafts already assume the following, so keep them true:
- **One asset id space and a property record per asset** (owner, basis, shares, use rights, disputes; ECONOMY §3.5 `PropertyRecord`), from C1's allocator; industry keeps its own per-asset record keyed by the C1 asset id (a `Facility`, a `Vehicle` with its own node, crew and bins, a `PowerLink`). So the C1 record must not assume a fixed node for every asset kind (a mobile asset's location lives in the owning package's record) and must expose `Assets.Create`, `Assets.Transfer` (sale, gift, seizure, inheritance: changes the owner of the property record with a basis and emits the ownership events) and `Assets.Destroy`.
- **Property records also for claimable non-assets**: sources, sites and (later) mineral deposits are claimed through C1's `SourceClaimed` (275) on a property record; keep the claim API general (`Property.Claim(thing ref, claimant, basis)`).
- `AssetKind` is data (a definition table), never an enum switch in code; industry adds kinds and its own `ObjClass` block (the drafts propose 110–129; that needs a contracts row) without editing `Work.cs`.
- **C1's work speed** (`1000 + 3 × skill`, tool and fatigue factors, ECONOMY §4.2) is referenced by the industrial runner: implement it as one public function even if skill is 0 in this run.
- **Theft of use** (using an asset, or connecting to a power line, without a right) must be classifiable like theft of goods: give `TheftCommitted` a `Kind (Goods | Use)` field from the start.
- Ownership spells and use rights cover any asset kind and any owner kind (`Org` included), with shares in permille, so a power station can be co-operatively or publicly owned and a vehicle leased; use rights admit an operator (`Work`) right on a mobile asset.
- Recipes allow several inputs and outputs per cycle and leave room for non-ware terms later (fuel and electricity) without changing existing rows.
- Output always belongs to the asset owner and is created only by `Goods.Produce`; no asset ever creates money or claims (D6.2).
