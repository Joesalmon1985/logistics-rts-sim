## 1. Objective
Actual resources are lent, used and then repaid or defaulted on (end-to-end scenario 7), recorded in a **double-entry `FormalObligation` registry** that never moves or creates goods. Lenders judge borrowers by their own **credibility** beliefs; promises are made, kept and broken; four signalling gestures (Thank, Greet, Threaten, Alarm) get their sim meaning.

## 2. User-facing outcome
In a population game with `Civ.Enabled = 1` the player can watch a loan handed over, the borrower eat or trade the goods, and later a repayment hand-over with a thank gesture, or a default followed by changed trust and a refused next request. The person card's Economy section (data in `CivCard`, drawn by U5) lists debts and claims **as the NPC believes them**, beside the registry truth in developer mode.

## 5. Allowed scope
1. **Registry** (`Civ/Obligations.cs`): `FormalObligation { int Id; Owner Debtor; Owner Creditor; ClaimUnit Principal; int Outstanding; int DueDay; int GraceDays; int Collateral /*ItemLotId, 0 none*/; ObligationSource Source (Loan, Pledge, Wage, Fee, Fine, Restitution, Tax, Deposit — Loan and Pledge used by C2; the rest reserved for C3/C6/C8/C9/C10); int RecordedBy /*OrgId, 0 none*/; int Deal /*DealId*/; ObligationStatus Status (Open, Settled, PartlySettled, Defaulted, WrittenOff, Orphaned); long OpenedTick, ClosedTick; int[3] WitnessedBy }` in `CivState.C2`, ascending id; `ObligationId` from `CivState.NextObligationId` (contracts §1), never reused. API (the **only** path): `Obligations.Open`, `Settle(id, amount)` (called after a physical repayment hand-over), `Default`, `WriteOff`, `Orphan` (debtor or creditor dead), queries by party. **Moves no goods.**
2. **Lending** (`Civ/Lending.cs`): terms agreed by gesture (`Offer` + `Promise`, `MsgTime` soon/later) with a `DealId`; `Lend` (97): lender hands over within `Reach.HandOver` — a **thing** with `OwnerRule.Keep` (ownership stays the lender's; return the same lot) or **consumables** with `ToReceiver` and basis `Loan`; the obligation opens at the hand-over (not at the agreement). `Repay` (98): borrower hands over (basis `Repayment`), `Settle` reduces `Outstanding` by exactly what moved.
3. **Default**: `CivSystem.DayStartC2` checks due obligations in ascending id; nothing repaid by `DueDay + GraceDays` (default 1) → `Default` (`LoanDefaulted`). Nothing restores the lender's goods.
4. **Collateral**: the borrower hands a lot to the lender with `OwnerRule.Keep`; on settlement the lender may hand it back (keeping it is theft, classified by C1); on default the lender **may** take ownership by `SetOwner(..., OwnershipBasis.Forfeited)` (its own decision; `CollateralSeized` 544).
5. **Credibility** in `CivMind` (C2 fields): believed obligations the NPC is party to (≤ 6, as it understood them — may differ from the registry) and per-person repayment memory (≤ 8 entries: on-time, late, defaulted counts), fed only by its own experience and by M5 gossip it perceived. The lend/refuse decision uses these through ordinary candidate scoring (`CivMindHooks.C2` candidates within the Civ quota 4), never the registry.
6. **Promises** 320–322: a `Promise` gesture about a future hand-over (not a loan) records `PromiseMade` and, at its time, `PromiseKept` or `PromiseBroken` (truth, from what happened); the promisee's memory updates through M5's existing deal memory where possible. Promises are **informal** (social memory) unless C6/C8 later records them.
7. **Signalling acts** 24–27 (Thank, Greet, Threaten, Alarm): compose and act on receipt through C2's mind-hook partials (Thank after a repayment or gift; Threaten as a repayment demand; Greet as a low-cost contact; Alarm as a warning of danger). If any of this needs an edit to `Comms/Messages.cs` or `Social/*` (M5 frozen files), stop and ask the lead for an amendment row.
8. **Death**: `CivHooks.OnDeath` partial (`C2`): obligations of the dead party become `Orphaned` (claims stay; nothing transfers automatically, as for estates).
9. `CivCard` rows for debts and claims (believed, layer 6) and registry truth (layer 1, developer mode only).
10. Scenario `DotNet/God.Runner/Scenarios/civ_lending.scenario.json` (scenario 7 fixture: two NPCs, varied trust, a hunger shock to create need).

## 22. Used later by industry (keep the interfaces general)
K2 (money and accounting core, `docs/stage4/MONEY_AND_ACCOUNTING_DESIGN.md` §3, §6, §12 requests K2-R4) and the industrial packages (`ELECTRICITY_DESIGN.md` bills, `INDUSTRIAL_RESOURCES_AND_PRODUCTION_DESIGN.md` supply contracts, `KNOWLEDGE_AND_TECHNOLOGY_DESIGN.md` licence fees and royalties, `INDUSTRIAL_MILITARY_DESIGN.md` procurement) will create **money claims**, deposits, bills, supply and licence obligations through this registry. Those drafts already assume:
- **The principal can name a money.** `Principal` is a `ClaimUnit { ClaimKind Kind (Ware | Money, later others); int UnitRef /*ware id or K2 money-unit id*/; int Amount }`, not a bare ware. C2 implements only `Ware`, but the shape, the save layout and the `0017` columns (`unit_kind`, `unit_ref`, `amount`) admit money without rewriting the migration.
- **`ObligationSource` is append-only** so K2 can add `Bill`, `LicenceFee`, `Royalty`, `AuctionPrice`, `Supply`, `Damages`, `Deposit` (MONEY K2-R4) by amendment, without renumbering C2's values.
- **Operations beyond C2's**: K2 asks for `Adjust` (account transfers) and `Accrue` (interest, Tier 3), and for a booking call on open, adjust and settle. Provide a single internal choke point (every state change of an obligation goes through one private method) with a **partial-method hook** (e.g. `static partial void OnObligationChanged(...)`) that a later package implements in its own file, so K2 does not edit `Obligations.cs`.
- `Debtor`/`Creditor` are `Owner` parties of any kind (`Npc`, `Household`, `Org`), so firms, utilities and governments are parties.
- Terms keep room for an instalment schedule and interest (`TermsId` referencing a terms record), unused in C2.
- `Settle` takes an amount and a settlement reference (a hand-over today; a K2 payment id later), and the double-entry invariant (ORG-I2, MON-I3) is stated per claim unit. Obligations never create goods or money (D6.2).
