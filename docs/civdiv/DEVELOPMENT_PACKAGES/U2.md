# U2: Divine HUD

Package spec for the Civilisation and Divinity run (owner brief 26 Nov 2026 §40). Self-contained. Paths start at the repository root. "Contracts" = [SHARED_ARCHITECTURAL_CONTRACTS.md](../SHARED_ARCHITECTURAL_CONTRACTS.md) (binding). This is a **view package**: the HUD reads only views (`IDivineView`, inspection cards) and writes only commands through `ICommandGate`; it never reads `GodState` (`HudViewOnlyTests`).

## 1. Identifier

**U2**, two parts: **U2a** (Tier 1, Checkpoint **B**, about 4.5 h) and **U2b** (Tier 2, Checkpoint **D**, about 2 h; restarts when D4a and D6 merge). Branches `unity/u2a` and `unity/u2b` (the index names the pair `unity/u2`), worktree `wt-lrs-u2` (reuse the warm folder for U2b on a new branch after U2a merged).

## 2. Objective

The hybrid diegetic and analytical interface for the god-only game (D5.22; brief §30): the player acts as a god, never as a government. U2a hides the 18 faction command paths when `GameSetup.Control == GodOnly` (blocker 6), adds the Mythic meter, the compact divine toolbar (Instruct, Miracle), the instruct popover (act, target, scope, expiry, validated with `Check` before `Submit`), the miracle tray, the Divine tab on the person card (layer-tagged), response chips, aggregated alerts, Unlimited and Disabled indicators, and makes the "Living island" menu start a god-only game at Checkpoint B. U2b adds the possession and avatar pills, the mode switcher, the commandment builder and list, and the spread view.

## 3. User-facing outcome

Checkpoint B: the player starts "Living island", sees a Mythic meter (balance, max, daily regeneration, a ghost segment for the cost of the armed power), a small toolbar; selects any villager (of any community) and suggests, commands or compels an act through a short form with no free text; sees "5 followed, 1 refused, 1 not reached"; heals or smites from the Miracle tray; reads the villager's Divine tab (what was issued, what they perceived, what they understood); gets a daily digest instead of a toast per trade or death. No build bar, no war buttons, no trade window in the god-only game. Unlimited shows an infinity glyph; Disabled hides the power slots. Checkpoint D: a possession pill (name, needs strip, upkeep, seconds left, Release), an avatar pill (health, carried object, gesture wheel, Dismiss), an A/B/C mode switcher, and the commandment builder: pick a template, adjust the structured fields, read the generated sentence and cost, reveal; a list of commandments with how many know and follow them.

## 6. Allowed scope

**U2a (Tier 1):**
- **God-only gating** (blocker 6): when `GameSetup.Control == GodOnly`, hide the build bar, HQ/road/demolish, war/peace/citadel, military marks/defend, trade, and the faction tutorial pointers; the stage 3 mode is unchanged (its tests stay). The sim refuses external faction commands anyway (`god_only`); the HUD must not offer them.
- **Divine HUD partials** under `Assets/God/Game/Hud/Divine/` (`GodHud.Divine.cs`, `GodHud.Divine.Meter.cs`, `GodHud.Divine.Toolbar.cs`, `GodHud.Divine.Instruct.cs`, `GodHud.Divine.Miracle.cs`, `GodHud.Divine.Card.cs`, `GodHud.Divine.Alerts.cs`), reading **only** `IDivineView` (D1) and the inspection cards, writing only through `ICommandGate` via U1's `PlayerCommandBuilder` (if U1a is not merged yet, a minimal local builder with the same signature that U1's replaces).
- **Mythic meter:** current over max, the daily regeneration figure, cost ghost for the armed power (red when unaffordable), upkeep drain when a spell is active (U2b), Unlimited (∞ glyph; spending still shown) and Disabled (greyed; power slots hidden).
- **Toolbar:** Inspect, Instruct (Suggest, Command, Compel as three distinct buttons, glyphs and colours), Miracle (Heal injury, Heal disease, Bless, Protect, Smite person/hut/source, Create, Destroy; Consecrate when D3c exists); arming a power works like the existing tool modes (`HudMode`), with `Gate.Check` validity on the hovered target and the cost chip; right-click/Esc cancels.
- **Instruct popover:** act (the Tier 1 `DivineAct` subset, unavailable ones greyed with `act_unavailable`), target (from the click, changeable by picking), scope (Person, Household, Group, Area, Location; Org later), expiry (defaults suggest 1 day, command 2 days, compel 600 ticks); no free text; `Check` before `Submit`.
- **Person card for anyone** in god-only mode (the divine view, not the faction view), with a **Divine tab** (issued / perceived / as-understood, response, the `Divine` term in the "why" line) whose rows carry their `KnowledgeLayer` label (authoritative vs belief, INFORMATION §12.4); the truth channel only where `TrueStateOverlayRules` allows.
- **Response chips and group tray:** "N delivered, N followed, N refused, N not reached" from `CommandResponded`; pending chips while paused.
- **Aggregated alerts:** a pure `AlertAggregator` (no Unity types, in `Hud/Divine/`, EditMode-game testable) replacing `ToastFeed` in the god-only game: critical individual cards (followed person dies, possession ended, Mythic exhausted), important aggregated cards per (class, cause, area, window), and one daily digest ("34 trades, 5 births, 3 deaths").
- **Menu:** "Living island" starts a god-only game (`GameSetup.Control = GodOnly`, `Setup.Human = NoHuman`, `Divinity.Enabled = 1`, `HumanGod` = the god of the first faction by default) **at Checkpoint B** (lead default: the flip happens with the re-pin); the old stage 3 "Play as Amber" stays. A three-way Mythic mode selector on the start card (Normal, Unlimited, Disabled) sends `SetMythicMode` in sandbox.
- `HudViewOnlyTests` extended: every new HUD type is added to `HudTypes`; none references `GodState`/`GodSim` for reading state (H-UI-4); a new test that the divine command types the HUD can send equal what an `IGodPolicy` may emit (DP10's UI half).
- Leave room for the **industrial workstream** (I6: vehicle inspection, power station and factory inspection, production queues, electricity/logistics overlays, shortage indicators; owner D6.19): the toolbar and card tab lists are data-driven (an array of tab and slot descriptors) so later packages add a tab or an overlay toggle without editing U2's drawing code (the industrial interface is being specified in a forthcoming PLAYER_UI_DESIGN §25; [ELECTRICITY_DESIGN.md](../../stage4/ELECTRICITY_DESIGN.md) already describes an electricity overlay, shortage glyphs and power-station inspection with the utility's own records beside the god's observation).
