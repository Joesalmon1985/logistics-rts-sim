# D2: Divine suggestions, commands and temporary compulsion

Package spec for the Civilisation and Divinity run (owner brief 26 Nov 2026 §40). Self-contained. Paths are relative to `Assets/God/Sim/` unless they start with `Assets/`, `DotNet/` or `docs/`. "Contracts" = [SHARED_ARCHITECTURAL_CONTRACTS.md](../SHARED_ARCHITECTURAL_CONTRACTS.md) (binding).

## 1. Identifier

**D2**, Tier 1, Checkpoint **B**. Interim merge **D2a** unblocks D6. Effort about 3.5 agent-hours. Branch `unity/d2`, worktree `wt-lrs-d2`.

## 2. Objective

The god issues an instruction (suggestion or command) with an act, target, scope and expiry; each recipient perceives it (or not) through its own perception, decodes it with M5's noise model, and **decides with its own policy** (brief §47 scenario 8). A compulsion temporarily forces a valid physical action, paid with Mythic, through the F1 control seam, never bypassing physical constraints (scenario 9; D5.7, D5.10).

## 3. User-facing outcome

The player selects a person (or household, hand-picked group, area) and suggests or commands an act such as "gather logs there". Some people follow, some ignore, some refuse; the reasons show in the person's "why" line (the `Divine` term). A compelled person walks past food while hungry to do what the god compelled, but a compulsion to give a fish it does not hold stays blocked, never conjured. The player sees which response happened (U2 draws the chips; U3b the effects).

## 6. Allowed scope

**D2a (interim; unblocks D6):**
- Handlers for `IssueSuggestion` and `IssueCommand { God, Act, Target, Scope, ExpireTicks }`: `Validate` (no mutation: god, Mythic via `Mythic.CanSpend`, act mapped, target valid, scope resolvable, `MaxRecipients` default 32); `Apply` (`TrySpend` first; `Interventions.Open`; recipients in ascending NpcId; `DivineSuggestionIssued` 810 / `DivineCommandIssued` 811).
- Perception: living persons only (`Bodies.IsLivingPerson`); asleep recipients perceive on waking (`Instruction.WakeDelivery`, default on); possessed recipients refused `already_controlled`; draw label `divine-perceive(npc, intervention)` against `Instruction.PerceiveChance` (suggestion 800, command 1000 per mille); `CommandPerceived` (813, HV, truth `Mismatch` at Full only).
- Decoding into `DivineMind.Inbox` (cap 4, oldest evicted) with M5's noise model, label `divine-decode(npc, intervention)`; suggestion noise `+SuggestionNoisePermille` (100), command clarity 255.
- `DivinityMindHooks.D2.cs`: `FillDivine` (inbox → `ThinkScratch.Divine`, read at the recipient's first think after delivery), `AddCandidates` (quota 4; the walk-then-act candidate named by `DivineActs.Map`; carries `Feature.Divine(Suggested 1 | Commanded 2)`), the **D2 part of `DivineTerm`**: `clamp(authority(kind) × Belief × max(Trust, Fear) / 1e6, ±2000)` with `authority` 1500 / 3000. Until D6 lands `GodBelief`, use the documented default belief/trust (tuning `Instruction.DefaultBelief`, `DefaultTrust`, both configurable; record the default in DEV_LOG).
- `Divinity/DivineActs.cs`: the `DivineActs.Map(act, target) → (learning verb, NpcVerb, IntentTarget)` table for the **Tier 1 subset** (MoveTo, Approach, Inspect as look, Gather, Take, Drop, Give, Eat, UseTool, Sleep, Trade, Communicate, Retreat, Treat as `Tend`); everything else refused at `Validate` with `act_unavailable` (never faked). The `Approach` act case and the `Drop` intent row through `DivinityHooks.TryAct` (D2 partial) if M3 has none.
- `CommandResponded` (814): exactly one per perceiver: `Followed`, `Ignored`, `Refused`, `Lapsed`, `Misread`; instruction expiry handled in `DivinitySystem`'s D2 slot (`D2Tick`/day start).
- Inbox rows on the Divine card (`Information/PeopleCards.Divine.cs`, D2 part): issued, perceived, as-understood as three items when they differ (INFORMATION §12.4).

**D2 complete:**
- `IssueCompulsion { God, Act, Target, ExpireTicks }` / `CancelCompulsion { God, Intervention }` through **`Control.TryAcquire`/`Release` only** (never editing `Control.cs` or `Think`); `CompulsionStarted` 815, `CompulsionEnded` 816 (reasons `Completed`, `Timeout` default 600 ticks, `Cancelled`, `Death`, `MythicExhausted`, `Superseded`), `CompulsionBlocked` 817; optional upkeep `Divinity.Upkeep.CompulsionPerTick`; learning tag `Feature.Divine(Compelled 3)`, `CompelLearnPermille` (1000), `SelfFeature.Compelled` (52) for `MemoryDays` (2).

- `OnDeath` partial (`DivinityHooks.D2.cs`): release compulsion (`Death`), close the dead recipient's instructions.

It is deterministic: integers, the seeded keyed `Rng` (`Rng.Fork(purpose, ids)`), no wall clock, no unordered enumeration (no dictionary iteration in rules). Bots and people use the same commands. `Assets/God/Game` only reads sim state, sends commands and animates events; it never mutates sim state. Sim code and its EditMode tests come before views; tests must also pass under `dotnet test DotNet -c Release`.
- **Contracts are binding.** [SHARED_ARCHITECTURAL_CONTRACTS.md](../SHARED_ARCHITECTURAL_CONTRACTS.md) wins over this spec and over the design documents. Commit the `.meta` files of new Unity folders and assets. Run `git status` before every commit.

  `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`
- **Commit as you go.** Long agents get cut off; small commits and the DEV_LOG record keep the work recoverable.

- **Compile before Unity (CLAUDE.md):** before any Unity open or test run, run `powershell -NoProfile -ExecutionPolicy Bypass -File AgentScripts/check-game-compile.ps1` from the worktree root; it must show 0 errors (it compiles `Assets/God/Game`, Editor and every test assembly without Unity). `dotnet test DotNet` alone never compiles the views.
