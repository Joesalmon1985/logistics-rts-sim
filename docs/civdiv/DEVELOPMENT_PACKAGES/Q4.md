## 16. Performance considerations
Unity runs take 45–100 minutes under throttling: start the final EditMode run as soon as the last fix lands; run the build in the same editor session; do not run benchmarks during the final window except `bench --compare` once.

## 17. Integration procedure
1. Freeze: announce it; no package merges after it except fixes.
2. For each fix: a branch is not required for a one-line fix with a test; otherwise the fixing agent's branch, merged by the lead after its gate.
3. Final gate as §13; tag; copy the build.
4. Documents: the helper drafts from run outputs, the lead reviews; commit messages via an ASCII file and `git commit -F`, ending `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
5. **Never push** (this spec) and never touch `main`; the owner decides on pushing.

## 18. Risks
- **God-mode smoke has no boot flag yet.** `GodBootstrap` knows `-godpopulation` but nothing starts a god-only game headless. U2a owns "the Living island menu start in god-only mode"; ask U2a (or U1a) to add a flag such as `-godgodonly` (sets `GameSetup.Control = GodOnly`, `Human = NoHuman`, `Divinity.Enabled = 1`, a schedule or idle god policy) with a PlayMode test, before Checkpoint B. Otherwise Q4-T6 cannot run and is reported as not run.
- **The final window shrinks** if late packages slip: enforce the cut plan; a missing Tier 2 feature is a listed deferral, never a half-merged branch.
- A late re-pin hides a real regression: every re-pin needs a stated cause.
- Unity throttling: keep one editor only; close it when done.
- `DEVELOPMENT_DEPENDENCY_GRAPH.md` (cut plan, slots, final window) does not exist yet: the lead must write it or adopt this spec's defaults.
