## 1. Objective
One executor for the twelve controls (`Motor`, §23.5): facing, steps, TAKE and DROP (including held-out lots, `Resisted`, grabbing from the incapacitated), SLEEP, WAIT, GESTURE (`Messages.Emit` plus `MsgExt`), and the **USE resolver** over catalogue `InteractionDef` rows with durations, progress and interruption; physical legality masks; the observation encoder `Percept` (`Obs v1`) over a simple correct `ISpatialIndex`; the possession adapter (`ControlInputKind.Primitive`); and the fixture harness that every later package uses to drive scripted primitive streams. Delivers QA-01 and MOTOR-1. The same code serves the trained policy, possession, avatars, compulsion, fixtures and the teacher.

## 2. User-facing outcome
Headless: a scripted stream of `PrimitiveControl` records moves, turns, takes, drops, sleeps, gestures and uses things on a unified world, deterministically, with identical physical results whatever the origin. A possessing player (UN10a later) and a trained brain (UN6 later) will submit the same records. There is no pathing for an NPC: movement is one lattice edge per step.

## 5. Allowed scope
1. **`Motor` bodies (§23.5):** `Submit`, `Tick` (advances action progress in ascending actor id), `Busy`, `Interrupt(reason)` (pain, collapse, strike, death), `Legal`. One action in progress per body; durations in ticks from data; every submission's `MotorStatus` is stored in `UnifiedNpc.LastResult` and is an input to the actor's next decision; failures emit `ControlFailed` 1221; `ControlApplied` 1220 at Full. **Origin changes nothing physical**; it is recorded on events only.
2. **Facing and steps (§D9.4 a):** facing is one of 6 world sectors (60 degrees); `StepForward`/`Back`/`Left`/`Right` resolve to the lattice neighbour nearest the facing sector (forward), its opposite (back) or +-90 degrees (left, right), ties by lower node id; no neighbour within +-30 degrees of the wanted sector means `Blocked`; impassable nodes (sea, from `ISpatialIndex.Walkable`) and occupied footprints are `Blocked`; `StepTicks` 6 (road 4, UB1), `TurnLeft`/`TurnRight` 1 tick, `WAIT` 10 ticks. A step moves exactly one lattice edge; there is no `MoveTo`, no multi-edge jump, and no pather behind a step. Facing, action progress and last result are saved and hashed.
3. **TAKE and DROP:** TAKE covers ground lots, storage bins, workstation output, containers, a person's **held-out** lot, and a person who is asleep, unconscious or dead (`MoveReason.Grab`); from an **awake** person's ordinary carry TAKE returns `Resisted` and is perceived by that person (seam `UnifiedHooks.OnTakeResisted`, UN7 emits 1283). A held-out lookup is a seam (`UnifiedHooks.HeldOutLookup`, default none; UN7 fills it): when a matching `HoldOut` exists the TAKE completes `Goods.Move(MoveReason.HandOver)`. DROP puts the lot on the ground at the actor's node. All moves use the single `Goods.Move` with `Reach.Of(why)`; capacity (`NoRoom`), weight and count (`NotEnough`), `OutOfReach`, `Occupied`/`Full` are the only refusals. Emit `ItemMoved` objective history (existing); `Grabbed` 1284 through `OnGrabbed`.
4. **SLEEP and WAIT:** SLEEP puts the body to sleep where it stands using the same sleep state and recovery the legacy body uses (reuse, read `Body()`/`StartSleep`); wake by recovery, by `Interrupt`, or by waking conditions already in the body code; a sleeper cannot submit another control except wake via interruption. Sleeping in a bed or spot is UN3b's `Occupy` effect plus SLEEP.
5. **GESTURE:** emits through `Messages.Emit` with the `GestureAct` value and a topic derived from the first referent (existing `Message` layout unchanged, quantity capped 0-9 there) **and** writes the unified side record `MsgExt { Message, R1, R2, Quantity (0-999), Corr }` for every unified GESTURE (§23.9). UN2 stores the `Corr` the control carries and does not allocate correlation ids (allocation and meaning are UN7's; section 18 gap). No gesture has a built-in meaning: `Offer`, `Promise`, `Claim`, `Threaten`, `Surrender`, `Accuse`, `Teach`, `Demonstrate` mean only what learning gives them.
6. **USE resolver (`Unified/Interactions/Resolver.cs`):** `USE(source or empty hand, target, slot)` matches `InteractionDef` rows from the `Catalogue` facade by (target kind, target catalogue id, slot 0-3 with 0 = first matching row, source requirement `EmptyHand | Ware | Class | Tool`), checks reach (`InteractionDef.Reach`), applies tool multipliers **to the duration only** (the source lot's `ObjectDef.ToolMultiplier`, minimum 1 tick; tools never gate an interaction), calls the effect handler's `Validate` at start (physical refusal statuses `NoInteraction`, `OutOfReach`, `NotEnough`, `NoRoom`, `Full`, `Occupied`, `Blocked`, `Busy`, `NotKnown`, `Disabled`), runs `Ticks` ticks of progress, and calls `Apply` at completion **only** (no output before completion). Interruption cancels the unfinished application; applications are short repeatable units, so completed units persist (UN4's labour unit, UN1's forage). Emits through the UN3b seams (`OnInteractionStarted/Completed` 1260/1261) and `ActionInterrupted` 1222; `Equipped` 1223 and `Unequipped` 1224 are **defined here** (UN8a's `Equip` effect emits them).
7. **Legality masks (`Motor.Legal`, `ActMask`):** physical legality only: exists, perceived, in reach, room, passable, not busy, and the design is one the person knows (`Knowledge.Knows`). Never a social, moral, "advisable" or ownership mask. `LegalPlacement` for `TargetKind.Placement` is a seam (UN4 fills; default false).
8. **Observation encoder `Percept` (`Unified/Percept/*`):** `Percept.Encode(GodState, actor, ref Percept)` and `Percept.ToVector(in Percept, short[] obs)` exactly per `Obs v1` (proprioception, 12 need pressures, health, injury, age band, temperament, up to 4 carried slots, the 6 neighbour cells, the **16 nearest perceived entities** sorted by distance then id with class, relative sector, distance and state bits, heard and seen gestures, memory slots, knowledge bits, divine inputs zero when divinity is off). Local only, through `ISpatialIndex`; **no truth query, no owner field, no path**; contents of a store are perceived only within reach or sight. Output length equals `ObsSchema` length.
9. **`SimpleSpatialIndex` (`Unified/Spatial/SimpleSpatialIndex.cs`):** a correct, deterministic implementation of `ISpatialIndex` (node-cell buckets rebuilt per tick over persons, buildings, sites, raw nodes, forage places, water points; query cost proportional to the cells touched; no all-pairs scan; sorted arrays, no `Dictionary` iteration). UNP may replace it behind the interface.
10. **Possession adapter:** `ControlInputKind.Primitive` entries (landed by UN0, routed to the `SubmitPossessed` seam) are validated by `Embodiment.CheckAction` against the same `Motor.Submit` (origin `Possessed`); a host may expand a click-to-move into step primitives labelled `Possessed`, **the sim never paths for an NPC**. `Embodiment.CheckAction` is in `Divinity/Possession.cs`, which is neither frozen nor in the index's owned list: this is a **flagged additive hunk**, gated by `Unified.On`, needing lead approval (section 18).
11. **Fixture harness** `DotNet/God.Runner.Tests/Support/PrimitiveFixture.cs`: builds a small unified world (stub start, configurable people, nodes, buildings and lots through UN0's APIs), submits scripted streams (`ControlOrigin.Fixture`), advances ticks, exposes physical state and hashes, records and replays streams. Every later package's mechanical tests use it. It also provides the origin-neutrality and replay assertion helpers.
12. `UnifiedHooks.UN2.cs`: fills `TickMotor` and `SubmitPossessed`.

## 6. Explicitly excluded scope
**D9 rules, binding on every line of this package** (amendment §§1-5, §D9.1, contracts §23):
- **No title, no permission.** The world records holder, location, quantity, condition, occupancy, labour and objective history; never a rightful owner, use right, membership gate or theft. No `.Owner`, `OwnerRelation`, `Permits.`, `StoreAccess`, `RightOn`, `Truth(` reference anywhere under `Unified/` or in a unified branch of a shared file (U-P3 static guard). A founder or contributor is provenance only. No adapter recreates title or access control; a claim is a brain belief, never world state.
- **No high-level verbs.** The only actions are the twelve `Prim` controls through `Motor.Submit`. No new learning `Verb`, `NpcVerb`, `MaxCand` change, goal table, `Build`/`Gather`/`Trade` action or `MoveTo` for an NPC; construction, collection, exchange and conflict are interaction effects reached by `USE`, `TAKE`, `DROP` and `GESTURE`.
- **No scripted behaviour.** No build order, shelter goal, profession, role, reciprocity, retaliation or "best site" selection in the game. A scripted teacher exists only in `DotNet/God.Train` and test fixtures, labelled `ControlOrigin.Teacher` or `Fixture`, and never drives an evaluation population.
- **Physical gates only.** A control may fail only for reach, inputs, capacity, weight, occupancy, passability, a physical barrier, time or a known-design requirement (`NotKnown` is a legality fact of the brain's knowledge, not a permission). A belief, claim, group, household, tribe or legacy owner field never blocks anything (EP-01).
- **One executor, origin-neutral.** Policy, possession, avatar, compulsion, fixtures and the teacher submit the same `PrimitiveControl`; origin is recorded on events and never changes a physical result (QA-01, U-P4).
- **Legacy untouched.** `Unification.Enabled = 0` is byte-identical to the base (U-P1). Legacy Stage 3, M3-M5 and C1-C7 code stays compiled and pinned; unified code never reads legacy ownership or permission paths (audit §8). Emit nothing rather than delete events.
- **Scale (D10).** Nothing is sized by tribe count, board size or population; every such number is configuration (23.1). Perception and witnesses go through `ISpatialIndex`; cost is O(active persons + changed entities) per tick; no all-pairs scan, no per-tick allocation on hot paths, no `Dictionary` iteration or wall clock; integers and keyed `Rng` forks with labels unique per call site.

Specific to UN2: no effect handlers beyond a counting stub for tests (UN1 `Forage`/`DrinkWash`, UN3b, UN4, UN7, UN8a own theirs); no catalogue content (UN3a; UN2 tests use code-defined test rows); no brain, inference, overlay or knowledge acquisition (UN6); no hold-out state, claims, correlation allocation or exchange events (UN7); no strike, injury or equipment logic (UN8a); no compulsion goal driver (UN9); no view or animation (UN10a); no `NodePather`, `MoveTo`, `Gather`, `Build` or any verb; no instinct table; no reuse of the legacy candidate builder; no change to the M5 `Message` layout; no grid `ISpatialIndex` optimisation (UNP).

## 16. Performance considerations
Scale rule (D10): perception goes only through `ISpatialIndex` (cost proportional to cells touched, no all-pairs); `Motor.Tick` is O(persons with an action in progress) in ascending actor id; the resolver is table lookup by catalogue id (sorted arrays); `Percept.Encode` writes into preallocated buffers (no allocation per decision); the observation is built **only when a person decides** (action completion), never every tick; `SimpleSpatialIndex` rebuild per tick O(entities). Budgets (report measured): at 1,200 persons the motor and index together under 1.5 ms per tick on the reference machine; encode under 20 microseconds per call; zero steady-state heap allocation in `Motor.Tick` and `Percept.Encode`. Level-of-detail or staggering, if ever needed, depends on sim state only, never on the camera.
